**Pattern to apply to all 4 routes:**

Current pattern (WRONG):
```typescript
const resend = new Resend(process.env.RESEND_API_KEY);  // Line 5-6 — crashes if undefined!

export async function POST(request: Request) {
    try {
        if (!process.env.RESEND_API_KEY) {
            if (process.env.NODE_ENV !== 'production') {
                console.warn('[DEV] RESEND_API_KEY missing — skipping email send');
                return NextResponse.json({ success: true, messageId: 'dev-skip', skipped: true }, { status: 200 });
            }
            return NextResponse.json({ error: 'Email service not configured' }, { status: 503 });
        }
        // ... rest of handler
    }
}
```

Fixed pattern (RIGHT):
```typescript
export async function POST(request: Request) {
    try {
        // Guard check FIRST
        if (!process.env.RESEND_API_KEY) {
            if (process.env.NODE_ENV !== 'production') {
                console.warn('[DEV] RESEND_API_KEY missing — skipping email send');
                return NextResponse.json({ success: true, messageId: 'dev-skip', skipped: true }, { status: 200 });
            }
            return NextResponse.json({ error: 'Email service not configured' }, { status: 503 });
        }

        // Initialize AFTER guard — guaranteed to have valid key
        const resend = new Resend(process.env.RESEND_API_KEY);

        // ... rest of handler using resend
    }
}
```

**Routes to fix:**
1. Development/app/api/send-onboarding-email/route.ts
2. Development/app/api/send-email/route.ts
3. Development/app/api/send-invoice/route.ts
4. Development/app/api/notify-existing-client/route.ts

Move `const resend = new Resend(...)` from module scope into POST handler, immediately after the guard check.

Why: Resend constructor throws when passed `undefined`. By checking the env var BEFORE calling the constructor, we avoid the crash. Request-time initialization also allows future multi-tenancy if needed.
