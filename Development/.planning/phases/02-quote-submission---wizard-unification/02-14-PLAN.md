# Phase 02 Plan 14: Critical Dependency Review - RLS Policy Decision Gate

## Objective

**CHECKPOINT: DECISION REQUIRED**

Get explicit decision on how to handle RLS policy for public document uploads before proceeding.

Purpose: Unblock Phase 02 UAT verification by resolving Phase 1/Phase 02 boundary issue
Output: Clear decision record and Phase 1 gap closure plan

## Issue

Public quote form submission fails when uploading bills because:
- Documents table has RLS enabled
- Current RLS policy blocks unauthenticated/public INSERT
- API endpoint cannot insert bills → quote creation fails

**This is NOT a Phase 02 bug.** It's a Phase 1 infrastructure gap that Phase 02 testing exposed.

## Three Options for RLS Documents Access

### Option A: Admin Bypass (RECOMMENDED)

**How it works:**
```typescript
// In /api/create-quote endpoint
const supabaseAdmin = createClient(url, serviceKey); // No RLS
await supabaseAdmin.from('documents').insert([...], { rls: false });
```

**Pros:**
- ✅ Simple one-line fix
- ✅ Clear intent: system-level operation
- ✅ Minimal surface area change
- ✅ RLS still protects user reads/updates

**Cons:**
- ⚠️ Document INSERT bypasses RLS during write
- ⚠️ Requires service_role key in API endpoint

**Risk Level:** Low
**Implementation Time:** 5-10 min
**Testing:** Verify quote submission works, documents saved

---

### Option B: RLS Policy Permitting Service Role

**How it works:**
```sql
CREATE POLICY "Allow service role document insert"
  ON public.documents
  FOR INSERT
  WITH CHECK (auth.role() = 'service_role');
```

**Pros:**
- ✅ Maintains RLS structure
- ✅ Explicit policy in database
- ✅ Auditable at DB level

**Cons:**
- ⚠️ Still needs service_role key
- ⚠️ Less clear which endpoints use service_role
- ⚠️ RLS policy sprawl (more policies to manage)

**Risk Level:** Moderate
**Implementation Time:** 15-20 min
**Testing:** Verify policy works, quote submission succeeds

---

### Option C: Authenticated Public User Account

**How it works:**
1. Create "public_system" user in auth.users
2. Sign in public users to this account for form submission
3. RLS policies check: `auth.uid() = (SELECT id FROM users WHERE email = 'public@system.local')`

**Pros:**
- ✅ Normal RLS flow
- ✅ Transparent auth handling
- ✅ Easier to audit (normal user context)

**Cons:**
- ⚠️ Requires auth session management
- ⚠️ Creates "fake" user account
- ⚠️ More complex implementation
- ⚠️ Potential security concerns with shared account

**Risk Level:** High
**Implementation Time:** 1-2 hours
**Testing:** Auth flow, session handling, RLS policies

---

## Recommendation: Option A (Admin Bypass)

**Why Option A:**
1. **Simplest to implement** - one-line change in API endpoint
2. **Lowest risk** - isolated to document upload, doesn't affect RLS for other operations
3. **Fastest to verify** - test quote submission immediately
4. **Clear intent** - API endpoint explicitly bypasses RLS for system operation (upload)
5. **Matches existing pattern** - API endpoints already use service_role for other operations

**Quote submission flow with Option A:**
1. Public user submits quote form (unauthenticated)
2. Frontend calls `/api/create-quote` with form data + bills
3. API uses supabaseAdmin (service_role) to insert documents with RLS bypass
4. API uses supabaseAdmin to insert quote record
5. Quote created successfully, bills linked to quote
6. User receives magic link for onboarding
