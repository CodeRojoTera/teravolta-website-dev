# Phase 02 Plan 13: RLS Policy Blocker - Phase 1 Carryover

Document and defer critical RLS policy issue blocking quote submission.

Purpose: Clear understanding of scope and dependencies between phases

## Execution Context

## Context

This is **NOT a Phase 02 fix** - it's a Phase 1 infrastructure issue being surfaced by Phase 02 testing.

### Issue Summary

**From UAT Test 3 - Quote Submission Failure:**

Error: "Failed to create quote" when submitting public quote form with bills uploaded.

Root cause analysis:
1. Quote form uploads bills to `documents` table via `/api/create-quote` endpoint
2. Public users are unauthenticated (user_id = null or system)
3. `documents` table has RLS enabled
4. Current RLS policy blocks INSERT for unauthenticated/public users
5. Quote creation fails before quote itself is saved

### Dependencies

The time picker fix (Plan 12) will make form submission reach the document upload step.
**But the RLS policy must be fixed for submission to complete.**

If RLS policy not fixed:
- Quote submission still fails (despite time picker fix)
- Users cannot proceed through public form
- Affects all three services (efficiency, consulting, advocacy)

### Phase Ownership

**Phase 1 scope:** "Data Integrity & Database Infrastructure"
- RLS policies are infrastructure-level
- Public document access is cross-service concern
- Should have been included in Phase 1 RLS work

**Phase 02 scope:** UI/UX quote form fixes
- Stops at form submission boundary
- Cannot proceed without Phase 1 RLS policy fix

## Required Action

**Defer to Phase 1 Gap Closure (after Phase 02 completes):**

Create new Phase 01 gap closure plan to:
1. Audit documents table RLS policies:
   - Current policy: Check what roles can INSERT
   - Needed policy: Allow public/unauthenticated INSERT for quote uploads
2. Fix RLS policy:
   - Option A: Bypass RLS in API endpoint (use `supabaseAdmin` with `rls: false`)
   - Option B: Add RLS policy permitting service_role INSERT for documents
   - Option C: Create authenticated user for public form submissions
3. Test public quote submission end-to-end:
   - Submit form with bills
   - Verify quote and documents saved
   - Verify no RLS violations in logs

## Decision Point

This plan is a **checkpoint:decision** - decide how to handle RLS for public document uploads:

**Option A: Admin Bypass (Recommended)**
- API endpoint runs with `supabaseAdmin.from('documents').insert()` with RLS bypass
- Pro: Simple, clear intent (system-level action)
- Con: Documents table not covered by normal RLS during insert
- Risk: Lower (insert only, no data leakage)

**Option B: RLS Policy Permitting Service Role**
- Add explicit RLS policy: `IF auth.role() = 'service_role' THEN true`
- Pro: Maintains RLS structure
- Con: Less clear which endpoints use service_role
- Risk: Moderate (requires tight control of service_role keys)

**Option C: Authenticated Public User**
- Create "public" user record in auth.users table
- Sign in public users to this account before submission
- Allow normal RLS logic for authenticated user
- Pro: Normal RLS flow, transparent
- Con: Extra complexity, auth session management needed
- Risk: Higher (broader authentication changes)
