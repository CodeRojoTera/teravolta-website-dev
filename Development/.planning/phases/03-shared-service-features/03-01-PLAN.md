  <action>
Update document category unions to include advocacy-specific values and consulting rfp, then validate uploads by service type.

- In `Development/lib/types.ts`, extend the `Document` category union to include `claim_evidence`, `regulatory_filing`, and `rfp`.
- In `Development/lib/documentUtils.ts`, extend the `UploadDocumentOptions` and related category unions to include the same values.
- In `Development/lib/schemas/constants.ts`, add `rfp` to the consulting category list in `SERVICE_DOCUMENT_CATEGORIES`.
- Import `SERVICE_DOCUMENT_CATEGORIES` and `ServiceType` from `Development/lib/schemas/constants.ts`.
- Add optional `serviceType?: ServiceType` to `uploadDocument` and `uploadMultipleDocuments` signatures.
- If `serviceType` is provided and a `category` is set, validate that the category exists in `SERVICE_DOCUMENT_CATEGORIES[serviceType]`.
  - If invalid, return `{ success: false, error: 'Category not allowed for service' }` without uploading or inserting a record.
  - Preserve existing behavior when `serviceType` or `category` is missing.
  </action>
  <verify>
Run:
```

```
Expect all files to include the new category values.
  </verify>
  <done>Document category types include advocacy categories plus consulting rfp, and upload helpers reject invalid service-category combinations when serviceType is provided.</done>
