<task type="auto">
  <name>Task 1: Add conversion readiness helper and map required fields</name>
  <files>
Development/lib/validation/quote-conversion.ts
Development/app/services/quoteService.ts
  </files>
  <action>
Create a shared helper to evaluate conversion readiness, and ensure quote data includes required fields.

- Add `Development/lib/validation/quote-conversion.ts` exporting:
  - `type QuoteConversionData` (service, amount, phases, timeline, budget, projectDescription, claimType, distributorCompany, claimAmount, incidentDate, damageDescription).
  - `normalizeQuoteForConversion(input)` that accepts either camelCase UI data or snake_case DB rows and maps into `QuoteConversionData`.
  - `getQuoteConversionReadiness(input)` returning `{ ready: boolean, missing: string[], warnings: string[] }`.
- Readiness rules:
  - consulting: timeline, budget, projectDescription required; phases required when quote amount > 0; every phase must have name and amount > 0; if amount is set, phase total must equal amount (allow small epsilon).
  - advocacy: claimType, distributorCompany, claimAmount, incidentDate, damageDescription required.
  - efficiency: always ready (no extra validation for conversion in this phase).
- Update `Development/app/services/quoteService.ts` `mapToType` to include:
  - `phases: row.phases || []`
  - advocacy fields mapped from `row.claim_type`, `row.distributor_company`, `row.claim_amount`, `row.incident_date`, `row.damage_description` (if present).
  - If the DB stores advocacy data in a `service_specific_fields` jsonb, map those keys as a fallback.
  </action>
  <verify>
Run:
```
rg "getQuoteConversionReadiness|claim_type|distributor_company|incident_date" Development/lib/validation/quote-conversion.ts Development/app/services/quoteService.ts
```
Expect the helper and mappings to be present.
  </verify>
  <done>Conversion readiness logic exists and quote data includes consulting/advocacy fields needed for evaluation.</done>
</task>
