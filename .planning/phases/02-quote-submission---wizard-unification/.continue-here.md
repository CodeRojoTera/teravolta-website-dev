## The Approach

Phase 02 is about **wizard unification** - making all 4 quote/project creation flows use the same components and validation logic.

### Why This Matters
- **Data consistency:** Same property types, same service fields across all entry points
- **Maintenance:** Change validation rules once, applies everywhere
- **Type safety:** Zod schemas + TypeScript catch errors at compile time

### The Pattern (Established)

1. **Foundation first (Plans 01-02):** Create shared schemas and components
2. **Refactor existing wizards (Plans 03-05):** Replace custom logic with shared components
3. **Polish (Plans 06-08):** Document filtering, admin edits, wiring

### Key Constraints

From 02-CONTEXT.md (user-locked decisions):
- **WIZ-02:** NO device_option or connectivity fields during quote submission
- **ADVO-11:** Advocacy quotes collect ONLY claim fields (no timeline/budget/projectDescription)
- **EE-04:** Inspection required for commercial properties (hotel/building/industrial)
- **CONS-13/14:** Consulting quotes require timeline AND budget

### The Refactor Recipe

For each wizard:
1. Replace `useState` form management → `useForm<QuoteFormData>()`
2. Add `zodResolver(quoteSchema)` for validation
3. Swap inline field rendering → shared components (PropertyTypeSelector, service fields)
4. Use helper functions for conditional logic
5. Preserve existing step flow and file upload handling
6. Test all 3 service types end-to-end

**Time estimate per wizard:** 15-30 minutes (based on Plan 02-03)

### What's Left

5 plans remaining, all following established pattern:
- 02-04: Customer wizard (768 lines, similar to public quote)
- 02-05: Admin wizard (ManualProjectWizard.tsx)
- 02-06-08: Document filtering, admin edits, wiring (lighter work)

**Estimated completion:** 1-2 hours in fresh session
